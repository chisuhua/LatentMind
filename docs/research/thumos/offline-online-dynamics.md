## 0. 核心问题

"训练阶段学习 + 推理阶段应用"的离线/在线双模式差异能否**内化为模型自身状态机**（不是服务部署模式），让单一模型在两种模式下展现不同的循环动力学？

**具体子问题**：

1. 训练阶段的多组件协同（ELF 训练 + Meta-Key 学习 + Adapter 训练 + 联合微调）能否内化为模型的"学习状态机"？
2. 推理阶段的检索-生成-触发协同能否内化为模型的"应用状态机"？
3. 离线/在线状态切换能否由模型自身检测（基于 Hidden State 统计），无需外部信号？
4. 多路 KV Cache 在两种状态下的共享策略如何内化（不依赖外部调度）？

---

## 1. 研究目标

定义 Thumos 内化离线/在线动力学的完整架构：

- (a) **训练状态机**：ELF / Adapter / Meta-Key / Nano-WM 的协同训练作为单一模型的状态
- (b) **推理状态机**：检索-生成-触发的循环作为单一模型的状态
- (c) **状态切换检测**：基于 Hidden State 统计的自动识别
- (d) **KV Cache 共享**：System Prompt KV 跨模式共享的内部管理

**赫尔墨斯契约 H4**（Internal State Export）路径默认关闭（INV-5），仅训练/调试时显式开启。

---

## 2. 最小验证单元

`InternalStateMachine` 模块：

- (a) 输入 = 模型 Hidden State 序列 + 训练/推理模式信号（可选外部）
- (b) 输出 = 当前模式分类（offline / online）+ 模式专属的循环策略
- (c) 支持模式切换时的平滑过渡（无性能损失）

**下游消费**：

| 状态 | 协同对象 |
|------|---------|
| 离线模式 | Phase 1-3 训练流水线的协同 |
| 在线模式 | 检索-生成-触发协同（[方向 1](./intent-internalization.md) + [方向 2](./fork-join-internalization.md)）|
| KV Cache 管理 | 三 Session 共享（Logos + Hippo + Intent）|

---

## 3. 关键指标

| 指标 | 计算方式 | 目标 |
|------|---------|------|
| 模式分类准确率 | Hidden State 统计自动识别 | ≥ 0.95 |
| 模式切换延迟 | 离线→在线（或反向）切换耗时 | < 10ms |
| KV Cache 共享率 | System Prompt KV 跨模式共享比例 | ≥ 0.6 |
| 训练→推理一致性 | 同一模型在两种模式下的任务表现 | 无显著退化 |
| INV-5 安全性 | 训练状态导出默认关闭 | 100% 关闭 |
| 端侧内存峰值 | 离线/在线状态下的 GPU 内存占用 | ≤ 同等规模非内化方案的 60% |

## 7. 64M 阶段 Riskiest Bet 实验

**离线/在线模式分类 + 切换延迟**：

| 实验 | 描述 | 评估指标 |
|------|------|---------|
| **模式分类** | Hidden State 统计自动识别离线/在线 | 准确率 ≥ 0.95 |
| **切换延迟** | 模式切换的端到端耗时 | < 10ms |
| **KV 共享** | System Prompt KV 跨模式共享 | 共享率 ≥ 0.6 |
| **一致性** | 同模型在两种模式下的任务表现 | 无显著退化 |
| **安全门** | 训练状态导出默认关闭 | 100% 关闭 |

**判定**：所有指标达标 ⇒ 内化离线/在线动力学假设成立；任一 🔴 失败 ⇒ 标记"未达阈值"，部分依赖外部调度。

## 9. 与 SADKO/Hippo 状态机的关系澄清

| 维度 | SADKO/Hippo 状态机 | Thumos 状态机（本方向）|
|------|------------------|---------------------|
| 范围 | 知识码本（FSQ codebook）的状态 | 模型自身的离线/在线状态 |

**关键区分**：SADKO/Hippo 状态机管"模型知道什么"，Thumos 状态机管"模型正在做什么"——两者正交。
